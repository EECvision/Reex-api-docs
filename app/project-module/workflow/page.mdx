# The Project Workflow

Project Mode connects the builder UI directly to your local codebase, creating a seamless loop between your API specifications and your frontend logic.

### Step 1: Import
Launch the builder using `reex-build`. Click **Import** to bring in your API collection.
- **Supported Formats**: Swagger/OpenAPI, Postman JSON.
- **Result**: Reex API Builder parses the file and prepares it for analysis.

### Step 2: Analyze & Generate
Once imported, click **Analyze**. The tool reviews the collection structure.

Click **Update Selected** to generate the code.

Reex API Builder updates the `api-services` folder in your project (the folder is initially created when you launch the UI with the `reex-build` command). At this stage, it:
- **Adds the `definitions` folder**: Contains the REST API version of the imported collection.
- **Updates the `generated` folder**: Generates the React Query version of the definitions.
- **Generates the `types` folder**: Automatically creates TypeScript interfaces for all endpoints.

### Step 3: The Two-Way Sync
Reex API Builder maintains a live link between the UI and your code.
- **UI to Code**: Actions in the Reex API Builder UI are automatically written to your local files. Generated interfaces are saved to your `types` files, while actions like deleting an API or module, deleting a collection, or generating an API template update your `definitions` files.
- **Code to UI**: Because `definitions` is the single source of truth, you can manually edit the TypeScript files in your IDE and the Reex API Builder UI will automatically detect these changes and update its display. Two files influence the UI:

  * **`config/constants`** — update the `baseURL` value to change the base URL across all requests.
  * **`definitions` files** — update individual API request functions directly. When doing so, ensure each endpoint function always accepts exactly one parameter — either a single primitive (e.g., `id: string`) or a single object (e.g., `{ id, payload }: { id: string, payload: UpdatePayload }`).
```typescript
    // ❌ Not acceptable — multiple parameters
    post_sendMessage: (channelId: string, payload: MessagePayload): Promise =>
      apiClient.post(`/channels/${channelId}/messages`, payload)

    // ✅ Acceptable — single object parameter
    post_sendMessage: ({ channelId, payload }: { channelId: string, payload: MessagePayload }): Promise =>
      apiClient.post(`/channels/${channelId}/messages`, payload)
```

### Step 4: Handling Updates (Diff View)
APIs change. When you re-import an updated Swagger or Postman file, Reex API Builder protects your code from silent overwrites.
- **Conflict Detection**: The tool compares the Incoming collection against your Current definitions.
- **Diff View**: You are presented with a side-by-side "Git-style" diff view. You can see exactly what changed (e.g., a new `firstName` string added to a payload) and decide whether to accept or reject the update.
